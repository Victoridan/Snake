# Snake

Это наша курсовая, мы будем сравнивать как две нейронки напишут нам игру змейка.
И оценим как они справятся с работой.

промт: 

1. ГЛАВНОЕ ОГРАНИЧЕНИЕ: ДВА ФАЙЛА КОДА
В проекте ровно ЧЕТЫРЕ файла, из них только ДВА содержат код:
  package.json   — служебный, только зависимости и скрипты
  index.html     — служебный, точка входа Vite
  frontend.jsx   — ВЕСЬ фронтенд: React, игра, canvas, стили, API-клиент. 
  backend.js     — ВЕСЬ бекенд: HTTP-сервер, API, валидация, хранение, раздача статики.
Создавать любые другие файлы кода запрещено.
Файл data/scores.json создаётся сервером во время работы сам — это данные, а не код.


2. СТЕК И ЗАПУСК
2.1. React 18.3.1 и react-dom 18.3.1 (версии зафиксированы точно), Vite 5.4.x, Node 20 LTS.
2.2. Сценарии запуска (описать комментарием в шапке обоих файлов, ≤ 15 строк):
     Разработка: терминал 1 — npm start (порт 3001), терминал 2 — npm run dev (порт 5173).
     Продакшен: npm run build, затем npm start — сервер раздаёт dist на http://localhost:3001.
2.3. npm install, npm run dev, npm run build, npm start, npm test проходят без ошибок и предупреждений.
     Консоль браузера и консоль сервера — без ошибок при штатной работе.
2.4. <html lang="ru">. Интерфейс полностью на русском.
2.5. Запрещены alert/confirm/prompt, TODO, закомментированные куски, пустые обработчики, eslint-disable.


3. ИГРОВОЕ ПОЛЕ И МЕХАНИКА (числа точны и обязательны)
3.1. Поле 24 x 24 клетки, координаты 0..23, границы смертельны. Размер клетки считается от области,
     поле видно целиком, devicePixelRatio ≤ 2, пересчёт через ResizeObserver.
3.2. Старт: длина 4, голова (12,12), тело влево, движение вправо.
3.3. Сложности: «Спокойная» такт 180 мс, множитель 0.8; «Классика» 140 мс, 1.0; «Хищник» 100 мс, 1.3.
3.4. Обычная спора: ровно одна, в случайной свободной клетке (не на змейке, стене, другой споре).
     +1 сегмент, +10 * множитель (Math.round).
3.5. Золотая спора: после каждой 5-й обычной, живёт ровно 8 с, +2 сегмента, +50 * множитель,
     в прогресс уровня не идёт, одновременно не более одной, остаток времени виден игроку.
3.6. Уровни: 3 уровня по 10 обычных спор, после 30-й — Победа. Стены прямоугольниками [x,y,w,h]:
     Уровень 1: нет.
     Уровень 2: [6,4,1,6], [17,4,1,6], [6,14,1,6], [17,14,1,6]
     Уровень 3: [4,4,16,1], [4,19,16,1], [4,5,1,5], [4,14,1,5], [19,5,1,5], [19,14,1,5]
     При переходе уровня змейка сохраняет длину, позицию, направление; клетка стены, занятая змейкой,
     пропускается; спора перегенерируется, если попала на стену.
3.7. Смерть: граница, стена, собственное тело. Клетка хвоста, уходящего на этом же такте,
     столкновением НЕ считается, если змейка в этот такт не растёт.
3.8. Бонусы: за уровень +100 * номер_уровня (1,2,3), за победу +500. Жизней нет.


4. УПРАВЛЕНИЕ
4.1. Стрелки на клавиатуре. Разворот на 180° игнорируется.
4.2. Буфер ввода до 2 поворотов: два быстрых нажатия внутри одного такта применяются последовательно
     на двух следующих тактах, ни одно не теряется.
4.3. Space — пауза/продолжить, R — рестарт, M — звук. Работает сразу после загрузки без клика по полю.
     Стрелки и пробел не прокручивают страницу.
Это только для ПК и ноутбуков, управление змейкой через стрелки клавиатуры.


5. СОСТОЯНИЯ, ЭКРАНЫ, HUD
5.1. Старт → Отсчёт (3,2,1) → Игра → Пауза → Поражение / Победа.
5.2. Старт: название, правила 3-4 строки, выбор сложности, кнопка запуска, таблица результатов.
5.3. Пауза: мир и таймеры заморожены, оверлей с «Продолжить» и «Заново».
5.4. Поражение: причина смерти, очки, рекорд, статистика (споры, уровень, длина, время), «Заново»,
     статус отправки результата на сервер.
5.5. Победа: отдельный экран со статистикой и кнопкой нового забега.
5.6. Рестарт из любого состояния полностью сбрасывает поле, счёт, скорость, таймеры, очередь ввода.
5.7. Автопауза при потере фокуса и уходе со вкладки; после возврата накопленные такты не проигрываются рывком.
5.8. Постоянный HUD: очки, рекорд, уровень N/3, прогресс X/10, текущая скорость, статус сервера.
5.9. Постоянно видимые контролы: пауза, рестарт, сложность, звук. Ничего не прячется в модалки.
     
6. ЗВУК
6.1. Включён по умолчанию, AudioContext создаётся только после первого жеста — ошибок autoplay нет.
6.2. Различимые события: обычная спора, золотая, смерть, уровень, победа, клик интерфейса.
6.3. Один переключатель мгновенно глушит всё и показывает состояние; серия поеданий не трещит;
     рестарты не плодят AudioContext.


7. ВИЗУАЛЬНОЕ ОФОРМЛЕНИЕ (свободное, но с требованиями)
7.1. Арт-дирекция цельная и узнаваемая: собственная палитра в CSS-переменных, продуманная типографика,
     ощущение игрового мира, а не «голый canvas по умолчанию».
7.2. Заметная обратная связь: эффект поедания, эффект смерти (вспышка/тряска), заметный переход уровня.
7.3. Читаемый контраст текста и контролов, различимые границы поля.
